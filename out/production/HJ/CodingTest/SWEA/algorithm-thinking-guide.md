# 알고리즘 문제 풀이 사고 순서 정리

## 1. 모든 알고리즘 문제의 기본 사고 순서

알고리즘 문제를 보면 바로 코드부터 쓰기보다, 먼저 아래 순서로 생각한다.

```text
1. 정답 단위 찾기
2. 필요한 정보 찾기
3. 저장해야 할 상태 정하기
4. 반복 방향 또는 탐색 방향 정하기
5. 작은 예시로 검증하기
6. 시간복잡도 확인하기
7. 코드로 옮기기
```

---

## 2. 정답 단위 찾기

가장 먼저 해야 하는 질문은 이것이다.

```text
내가 구해야 하는 1개는 정확히 뭐지?
```

정답 단위는 문제마다 다르다.

```text
개수
최댓값
최솟값
합
경로
경우의 수
특정 패턴
최단 거리
가능 여부
```

예를 들어 SWEA Magnetic 문제에서는 자석 좌표 개수가 정답이 아니다.

```text
정답 단위 = 세로줄에서 1 다음에 2가 나오는 패턴 1개
```

여기서 정답 단위를 잘못 잡으면 자료구조도 복잡해지고, 코드도 틀리기 쉬워진다.

---

## 3. 필요한 정보 찾기

그다음 질문은 이것이다.

```text
입력에서 어떤 정보가 실제로 필요하지?
```

모든 정보를 다 써야 하는 문제도 있지만, 어떤 문제는 일부 정보만 보면 된다.

Magnetic 문제에서는:

```text
가로 방향은 중요하지 않다.
각 열의 위아래 순서만 중요하다.
자석을 실제로 한 칸씩 움직일 필요도 없다.
```

즉, 필요한 정보는 이것이다.

```text
각 세로줄에서 1과 2가 어떤 순서로 나오는가
```

---

## 4. 저장해야 할 상태 정하기

다음 질문은 이것이다.

```text
전체를 저장해야 하나?
아니면 이전 상태 하나만 기억하면 되나?
```

Magnetic 문제에서는 `Set<Node>` 같은 좌표 저장이 필요하지 않다.

필요한 상태는 하나뿐이다.

```java
boolean hasN = false;
```

의미:

```text
현재 열에서 위쪽에 아직 짝을 만나지 않은 1을 본 적이 있는가?
```

`1`을 만나면:

```java
hasN = true;
```

그 뒤에 `2`를 만나면:

```java
answer++;
hasN = false;
```

이렇게 교착 하나가 완성된다.

---

## 5. 반복 방향 또는 탐색 방향 정하기

그다음은 어느 방향으로 볼지 정한다.

```text
왼쪽에서 오른쪽
오른쪽에서 왼쪽
위에서 아래
아래에서 위
시작점에서 퍼지기
정렬 후 앞에서 뒤
```

Magnetic 문제에서는:

```text
각 열마다 위에서 아래로 본다.
```

그래야 `1` 다음에 나오는 `2`를 자연스럽게 셀 수 있다.

## 7. 시간복잡도 확인하기

반복문을 짠 뒤에는 입력 크기에서 가능한지 확인한다.

Magnetic 문제는 보통 `100 x 100` 크기이다.

```text
O(N^2)
```

이 정도는 충분히 가능하다.

---

## 8. Magnetic 문제 정답 구조

```java
int answer = 0;

for (int col = 0; col < N; col++) {
    boolean hasN = false;

    for (int row = 0; row < N; row++) {
        if (board[row][col] == 1) {
            hasN = true;
        } else if (board[row][col] == 2) {
            if (hasN) {
                answer++;
                hasN = false;
            }
        }
    }
}
```

생각의 흐름:

```text
1. 정답 단위는 1 -> 2 패턴이다.
2. 열마다 위에서 아래로 보면 된다.
3. 위에서 1을 봤는지만 기억하면 된다.
4. 1 이후에 2가 나오면 교착 1개다.
5. 교착을 세면 다시 새로운 1을 기다린다.
```


자주 나오는 풀이:

```text
단순 반복문
상태 변수
카운팅
정렬
문자열 패턴 체크
```

예시 사고:


## 9-2. 시뮬레이션 문제

먼저 생각할 질문:

```text
1. 진짜로 과정을 전부 구현해야 하나?

3. 한 단계에서 무엇이 변하지?
4. 동시에 움직이는가, 순서대로 움직이는가?

```

```text
문제에서 움직인다고 해서 반드시 실제로 움직여야 하는 것은 아니다.
```

Magnetic 문제도 자석이 움직이는 설명이 있지만, 실제 이동 시뮬레이션은 필요 없다.


예시 사고:


## 9-4. BFS 문제

BFS는 최단 거리, 최소 이동 횟수 문제에서 자주 쓴다.

먼저 생각할 질문:

```text
1. 상태가 무엇인가?
2. 한 번 이동하면 어디로 갈 수 있는가?
3. 방문 체크 기준은 무엇인가?
4. 시작점은 어디인가?
5. 도착 조건은 무엇인가?
6. 최단 거리 문제인가?
```

자주 쓰는 자료구조:

```java
Queue<Node> queue = new ArrayDeque<>();
boolean[][] visited = new boolean[N][M];
```

예시 사고:

```text
정답 단위: 최소 이동 횟수
필요한 상태: 현재 위치, 이동 거리
반복 방향: 현재 위치에서 갈 수 있는 곳으로 퍼지기
```

---

## 9-5. DFS 문제

DFS는 연결 요소, 깊은 탐색, 모든 경우 탐색에서 자주 쓴다.

먼저 생각할 질문:

```text
1. 현재 위치 또는 현재 상태가 무엇인가?
2. 다음으로 갈 수 있는 곳은 어디인가?
3. 방문 처리가 필요한가?
4. 재귀 종료 조건은 무엇인가?
5. 모든 경로를 봐야 하는가?
```

자주 쓰는 형태:

```java
static void dfs(int x, int y) {
    visited[x][y] = true;

    for (int d = 0; d < 4; d++) {
        int nx = x + dx[d];
        int ny = y + dy[d];

        if (범위 안이고 방문하지 않았다면) {
            dfs(nx, ny);
        }
    }
}
```

## 9-6. DP 문제

DP는 이전 결과를 이용해서 현재 결과를 만드는 문제이다.

먼저 생각할 질문:

```text
1. dp[i]가 무엇을 의미하지?
2. dp[i]를 이전 값으로 만들 수 있나?
3. 초기값은 무엇인가?
4. 점화식은 무엇인가?
5. 계산 순서는 앞에서 뒤인가, 뒤에서 앞인가?
```

DP에서 제일 중요한 것은 `dp`의 의미를 정확히 정하는 것이다.

예시:

```text
dp[i] = i번째까지 봤을 때의 최대값
dp[i][j] = i, j 위치까지 왔을 때의 최소 비용
dp[i] = i를 만드는 경우의 수
```

## 9-7. 이분탐색 문제

이분탐색은 정답 후보가 숫자 범위로 잡히고, 가능/불가능이 나뉘는 문제에서 쓴다.

먼저 생각할 질문:

```text
1. 정답 후보를 숫자 범위로 잡을 수 있는가?
2. 어떤 값 x가 가능하면 그보다 큰 쪽 또는 작은 쪽도 일정하게 가능한가?
3. check(x)는 무엇을 반환해야 하는가?
4. 최소 가능한 값을 찾는가, 최대 가능한 값을 찾는가?
```

핵심 구조:

```text
정답을 직접 찾기 어렵다면,
"이 값이 정답이 될 수 있나?"를 검사한다.
```

그리디는 매 순간의 선택이 전체 최적해로 이어지는 문제에서 쓴다.

먼저 생각할 질문:

```text
1. 지금 무엇을 선택해야 하지?

3. 지금 선택해도 나중에 손해가 없나?
4. 반례가 있나?
```

자주 나오는 기준:

```text

가장 큰 것부터
끝나는 시간이 빠른 것부터
```

그리디는 감으로 풀면 위험하다.

## 9-9. 정렬 문제

먼저 생각할 질문:

```text
1. 무엇을 기준으로 정렬해야 하지?
2. 오름차순인가, 내림차순인가?
```

## 9-10. Set, Map을 쓰는 문제

먼저 생각할 질문:

```text
1. 중복 제거가 필요한가?
2. 빠른 검색이 필요한가?
3. 개수를 세야 하는가?
4. key와 value 관계가 필요한가?
```

`Set`을 쓰는 경우:

```text
중복 제거
존재 여부 확인
```

`Map`을 쓰는 경우:

```text
값의 개수 세기
key별 정보 저장
빠른 조회
```

Java에서 직접 만든 객체를 `HashSet`이나 `HashMap`의 key로 쓰려면 `equals()`와 `hashCode()`가 필요하다.

```java
class Node {
    int x;
    int y;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Node)) return false;
        Node node = (Node) o;
        return x == node.x && y == node.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }
}
```

Java 16 이상이면 `record`를 써도 된다.

```java
record Node(int x, int y) {}
```

# 11. 알고리즘 문제 풀이용 체크리스트

문제 풀기 전에 아래 3줄을 먼저 적는다.

```text
정답 단위:
필요한 상태:
반복 방향:
```

조금 더 자세히 적고 싶으면 이렇게 쓴다.

```text
정답 단위:

```

Magnetic 문제에 적용하면:

```text
정답 단위: 1 다음에 2가 나오는 패턴 개수

```

# 12. 가장 중요한 요약

알고리즘 문제를 볼 때 가장 먼저 할 일은 이것이다.

```text
정답 단위를 먼저 잡는다.
필요한 상태를 최소로 줄인다.
반복 방향을 정한다.
작은 예시로 검증한다.
그다음 코드로 옮긴다.
```

이번 Magnetic 문제에서 배울 핵심은 이것이다.

```text
문제가 자석의 움직임처럼 보여도,
실제로는 세로줄에서 1 -> 2 패턴을 세는 문제였다.
```

즉, 문제를 잘 푸는 핵심은 자료구조를 많이 아는 것만이 아니다.

```text
무엇을 세야 하는지 정확히 잡는 것
필요 없는 움직임이나 저장을 줄이는 것
상태 하나로 표현할 수 있는지 보는 것
```

이 세 가지가 먼저다.
